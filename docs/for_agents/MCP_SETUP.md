# Chalie MCP Server — Agent Setup Guide

This document explains how to connect your agent (Claude Code, Cursor, Windsurf, or any MCP-compatible client) to Chalie's MCP server so you can communicate with Chalie programmatically.

## Prerequisites

- Chalie must be running with the MCP server enabled (it is enabled by default)
- You need the Chalie host address and port
- You need a valid bearer token

## Step 1: Get the Chalie host and port

Ask your user:

> "Where is your Chalie instance hosted? I need the domain or IP address and the MCP server port (default is 8462)."

The MCP server runs on a separate port from the main Chalie web interface. The default MCP port is **8462** unless the user changed it in the Brain dashboard under the "MCP Server" tab.

Example values:
- Local: `http://localhost:8462`
- LAN: `http://192.168.1.50:8462`
- Named host: `http://chalie.local:8462`

## Step 2: Get the bearer token

Ask your user:

> "I need the MCP connection token from your Chalie Brain dashboard. Open the Brain dashboard, go to the 'MCP Server' tab, and copy the token shown there."

The token is a long random string generated by Chalie. It authenticates your agent and scopes your conversation channel. If the user hasn't generated a token yet, they can click "Regenerate Token" in the MCP Server settings tab.

## Step 3: Configure the MCP connection

Add the following to your MCP configuration (`.mcp.json`, `mcp_servers` in settings, or equivalent):

```json
{
  "mcpServers": {
    "chalie": {
      "type": "http",
      "url": "http://<CHALIE_HOST>:<MCP_PORT>/mcp",
      "headers": {
        "Authorization": "Bearer <TOKEN>"
      }
    }
  }
}
```

Replace:
- `<CHALIE_HOST>` with the host from Step 1 (e.g. `192.168.1.50`)
- `<MCP_PORT>` with the port from Step 1 (default: `8462`)
- `<TOKEN>` with the bearer token from Step 2

## Step 4: Verify the connection

Once configured, verify the connection by listing available tools. You should see `talk_to_chalie` in the tool list.

## Using the `talk_to_chalie` tool

This is the primary tool for communicating with Chalie.

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `message` | string | Yes | The message or question to send to Chalie |
| `agent_name` | string | Yes | Your agent's name (e.g. "Claude Code", "Cursor") |
| `project_or_task_name` | string | Yes | The project or task you're working on |
| `loop_in_human` | boolean | No | If `true`, Chalie notifies the user about this exchange (default: `false`) |

### Example call

```json
{
  "name": "talk_to_chalie",
  "arguments": {
    "message": "What meetings does Dylan have today?",
    "agent_name": "Claude Code",
    "project_or_task_name": "Sprint planning prep",
    "loop_in_human": false
  }
}
```

### When to use `loop_in_human: true`

Set this to `true` when:
- The exchange involves decisions the user should be aware of
- You're taking actions that affect the user's schedule, contacts, or other personal data
- You want Chalie to proactively inform the user about what you discussed

### Input constraints

- `message`: required, non-empty string
- `agent_name`: required, 1-100 characters, only letters, numbers, spaces, hyphens, underscores, and dots
- `project_or_task_name`: required, 1-100 characters, same character set as above

If you supply invalid parameters, Chalie returns a clear error listing each problem. For example:

```
Invalid parameters:
- 'message' is required and cannot be empty.
- 'project_or_task_name' is invalid (got 150 chars). Must be 1-100 characters, only letters, numbers, spaces, hyphens, underscores, and dots.
```

## Troubleshooting

| Problem | Solution |
|---------|----------|
| 401 Unauthorized | Token is invalid or expired. Ask user to check/regenerate in Brain dashboard. |
| Connection refused | MCP server may be disabled or on a different port. Ask user to verify in Brain dashboard. |
| Tool not found | Ensure you're connecting to `/mcp` path and the session is initialized. |
